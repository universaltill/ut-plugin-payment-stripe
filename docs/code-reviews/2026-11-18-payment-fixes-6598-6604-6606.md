## 1. ut-plugin-payment-stripe (v1.6.0 -> v1.7.0, branch fix/fable-stripe)

### What shipped
- #6598: refund sends `Idempotency-Key: ut-refund-<event id>-<PaymentIntent>`. Core's refund event id is `refund_attempt_id:<payload+guard digest>`, stable across a re-tap of the same form and new after any committed refund, so a lost-reply retry replays Stripe's first answer (no double refund, full refund recordable, no move to the other leg).
- #6604: `currency` is a choice with `auto` (default). Order: saved pin, else the sale's currency (core sends it since #5033), else `shop.context.v2`; mismatch declines `currency_mismatch`, unknown declines `currency_unknown`. Adds `view:shop` + `views_used: shop.context.v2` (same as the SumUp manifest).
- #6606: `saveAuthorizeResult` copies the map, so stdout never carries `recent`.
- #6600: decline answer (`decline_code`, e.g. `outcome_unknown`) pinned on stdout at exit 2.

### Verification
- `go test ./...`, wasip1 `go vet`, wasm build, `scripts/validate.sh` (ok v1.7.0), `scripts/guard-plugin-i18n.sh`: all green.
- `view:shop` is a real core permission (`internal/data/core_views.go:400`, `shop.context.v2`). On update it arrives **not granted** (`InsertPluginPermissions`, granted=0) until the owner approves; harmless because core sends the sale currency on authorize. Only a pre-#5033 core with `auto` and no grant would decline `currency_unknown`.
- Mutations (all killed): idem key blanked -> 4 refund tests fail; `recent` written back to the answer -> `TestSaveAuthorizeResultDoesNotAddRecentToTheAnswer` fails; mismatch check disabled -> `TestResolveCurrency` fails.

### Findings
- Low (accepted): Stripe caches executed error answers per Idempotency-Key for 24 h. A definite failure (e.g. `balance_insufficient`) re-tapped on the same form replays the error; reloading the refund page mints a new key. SumUp clears its record on a definite failure; Stripe can't. Write it in the README.
- Low (pre-existing, follow-up): `recent.go:160` orders legs by `o.Amount+o.TipAmount`, but core's payment `amount` already includes the tip (`applyPluginReportedTip`), so the tip counts twice.
- Info: `refund_amount` (new core field, #6603) is not read yet, so a two-card full refund still declines.

### Verdict
Approve.
